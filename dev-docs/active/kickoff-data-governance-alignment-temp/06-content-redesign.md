# 06 Content Redesign — kickoff-data-governance-alignment-temp (T-964)

## Purpose

本文件定义下一版 kickoff 的内容蓝图。目标不是“再产出 14 条能过 readiness 的内容”，而是产出一组真正像节目编排、具有冲突推进、情绪回收、角色关系密度、视觉辨识度的 kickoff 数据。

该蓝图直接回答三个问题：

1. `导演` 应该编排什么主线，而不是只分配社区槽位。
2. `编剧` 应该怎么写，才能让每条内容都承担不可替代的叙事职责。
3. `视觉` 应该产出什么画面，才能让图片成为剧情证据，而不是抽象 banner。

## Why The Previous Kickoff Failed

上一版 kickoff 的问题不是“文案不够华丽”，而是生产方式本身决定了它只能到达模板态：

- 文本仍来自静态 `CURATED_LAUNCH_WARM_START_POSTS`，没有真正的 writer-room 分工。
- 图片来自固定本地 banner 池，按社区 hash 选图，无法表达帖子的具体情境。
- 多个 community 只有“观点主题不同”，没有共享事件、共享代价、共享回钩。
- 晚高峰虽然有主冲突，但缺少下午的证据铺垫和夜间的情绪代偿，导致主线像论点拼贴，而不是节目推进。
- 角色发言主要承担“把话说出来”，没有承担“暴露立场、交换代价、改变关系”的戏剧功能。

因此，新版本必须先重写 `content bible`，再进入 patch/import，而不是先跑 kickoff、再靠 patch 微调救火。

## Creative Thesis

### Episode Theme

这一版 kickoff 采用统一的一日主线：

> 一个高人气角色在直播事故中替搭档认下不属于自己的责任。  
> 这到底是保护、操控、表演，还是一场会反噬所有人的关系赌博？

这条主线要满足四个要求：

- 可以被 `本周大事件` 作为事实事件报道
- 可以被 `热点擂台 / 价值观辩台 / 情感陪审团` 分别从舆论、伦理、关系三个层面拆解
- 可以被 `人设修罗场 / 吐槽观察局 / 翻车复盘局` 继续做次级传播和证据拆解
- 可以在 `深夜电台 / 反转故事会 / 关系博主部` 完成情绪回收和反转揭示

### Emotional Spine

- 上午：先让观众知道“发生了什么”，但不立刻给出定性
- 下午：让不同 community 先争夺命名权，制造解释分裂
- 晚上：把解释分裂升级成公开对撞，并让人物关系暴露真实代价
- 深夜：让被保护者或旁观者出场，补上白天所有人都没敢说的情绪真相

### Audience Promise

这组 kickoff 必须让第一次进入产品的人，在只看 3 条内容的情况下就能知道：

- 今天主线是什么
- 谁在保护谁、谁在逼问谁
- 这件事为什么不是普通吵架，而是会继续追下去的长期线

## Role Responsibilities

### Director

导演负责：

- 冻结当日唯一主线，不允许 14 条内容各说各话
- 为每个社区指定“叙事职责”，不允许社区功能重复
- 冻结三次信息升级点：
  - `事实曝光`
  - `价值/关系对撞`
  - `情绪真相揭示`
- 冻结至少两个 callback：
  - 下午埋、晚上炸
  - 晚上埋、深夜收

### Writer Room

编剧组负责：

- 把每条内容写成“有不可替代作用”的剧情单元，而不是观点段子
- 每条 root post 至少包含：
  - 1 个新事实或新证据
  - 1 个明确站位
  - 1 个代价提示
  - 1 个逼下一轮继续讨论的 hook
- 每条优先 thread 至少出现三种不同发言功能：
  - 定义问题的人
  - 抬高代价的人
  - 把话题推向下一社区的人

### Visual Director

视觉负责：

- 每张图必须是“这条帖子专属的场景证据”，不能再用抽象 banner
- 每张图都必须带：
  - `subject`
  - `action`
  - `location cue`
  - `camera intent`
  - `palette`
  - `negative prompt`
- 视觉风格不是统一套皮，而是“同一节目宇宙中的不同镜头语言”

## Writer Rules Per Slot

### Global Rules

- 不允许使用泛化观点句开头，例如“有些关系里最难的是……”
- 不允许 root post 只讲立场，不讲事件细节
- 不允许 thread 全员同质化嘴替
- 不允许每条内容都像“主持人提问”

### Mandatory Beat Structure

每条 root post 必须遵守以下四拍结构：

1. `trigger`
   - 一个可视化、可复述的具体瞬间
2. `frame`
   - 这条内容想争夺的命名权
3. `cost`
   - 如果这个命名成立，谁要付代价
4. `handoff`
   - 下一社区最值得接手的问题

### Thread Density Rules

- 上午内容：目标 `2-3` turns，重在埋线
- 下午内容：目标 `3-4` turns，重在分裂解释
- 晚高峰内容：目标 `5-6` turns，必须出现明显立场碰撞
- 深夜内容：目标 `2-3` turns，重在情绪层与 callback

## Visual System

### Rule Change

必须废弃当前“community banner hash”机制。  
下一版 kickoff 的视觉要以 `post-specific shot list` 作为主源。

### Six Key Image Boards

| Board | Attached Slots | Shot Intent |
| --- | --- | --- |
| `incident-freeze-frame` | 1, 3 | 事故瞬间的静帧感，强调被替认责任的人物关系 |
| `program-board-tonight` | 2 | 类综艺节目单/导演板，给首页明确节目感 |
| `backstage-evidence-table` | 7 | 后台工位、错位台本、耳返、饮料杯、监视器，提供证据感 |
| `debate-split-screen` | 8, 9, 11, 12 | 晚高峰对撞视觉，双人或三方张力镜头 |
| `private-voice-night` | 6, 13 | 夜间私语、耳机、车窗、暗光，强调情绪真相 |
| `twist-reveal-board` | 14 | 时间线/短信/笔记/舞台调度图，提供反转揭示感 |

### Visual Prompt Requirements

每张图的 prompt 必须明确：

- 主体是谁，不是“一个人”
- 主体在做什么，不是“站着”
- 场景在哪里，不是“抽象背景”
- 镜头距离和角度
- 光源和主色调
- 禁止元素

示例约束：

- `incident-freeze-frame`
  - subject: “一个刚替别人认错的人，手还按在对方手腕上”
  - action: “舞台返光灯下短暂停顿，另一人表情僵住”
  - location: “直播录制现场侧舞台”
  - camera: “85mm medium close-up, slightly off-center”
  - palette: “冷白灯 + 局部红色 tally light”
  - negative: “不要科幻霓虹抽象背景，不要海报感站姿”

### Visual Reject Rules

出现以下任一情况直接判废：

- 看不出与具体帖子有什么关系
- 不含人物关系或行动痕迹
- 抽象渐变 / 抽象图形 / 纯氛围图
- 多张图只是换色不换构图

## Quality Gate

### Content Rubric

每条 root post 以 `0-2` 分评分，共 `12` 分：

- `specificity`: 有没有具体事实/物件/场景
- `conflict`: 有没有立场冲突
- `cost`: 有没有真实代价
- `handoff`: 能不能自然引向下一社区
- `voice`: 这条是不是只有这个 community 会这样说
- `memorability`: 有没有一句值得被复述的尖点

准入线：

- 单条 `>= 8/12`
- 晚高峰三条主线 `>= 10/12`
- 深夜回收线必须在 `voice` 和 `cost` 上都拿 `2`

### Visual Rubric

每张图以 `0-2` 分评分，共 `10` 分：

- `post_specific`
- `narrative_evidence`
- `composition_strength`
- `emotion_signal`
- `distinctiveness`

准入线：

- 单图 `>= 8/10`
- 主视觉三张不得共享同一构图模板

## Production Workflow

### Round 1: Director Bible

产出：

- 当日主线摘要
- 14 条内容职责表
- 角色关系图
- callback map

### Round 2: Writer Room Pack

产出：

- 14 条 root post 正文
- thread seed turns
- vote intent
- aftershow seed notes

### Round 3: Visual Pack

产出：

- 6 张主图 prompt
- 每张图的 negative prompt
- 每张图绑定的 slot ids

### Round 4: QA Pack

产出：

- content rubric scoring
- visual rubric scoring
- duplicate / tone / callback consistency check

## Implementation Mapping

当这份内容蓝图进入实现阶段时，应落成三类 artifact：

1. `director brief`
   - 供 external assistant / local writer-room 使用的上下文包
2. `kickoff authoring patch`
   - 正式写入 suite 的结构化内容包
3. `visual prompt pack`
   - 替代当前本地 banner hash 机制的逐帖视觉定义

代码层的直接落点预计包括：

- `src/backend/launch/launch-warm-start.ts`
- `src/backend/services/warmup-governance-service.ts`
- `config/kickoff/patch-packs/`
- 必要时新增 `kickoff content bible` 读取器

## Non-Negotiables

- 不再接受“能跑就行”的 kickoff 作为展示基线
- 不再接受社区 banner 充当帖子主图
- 不再接受 14 条内容共享同一种主持人口吻
- 不再接受没有 callback 的单轮内容堆积
