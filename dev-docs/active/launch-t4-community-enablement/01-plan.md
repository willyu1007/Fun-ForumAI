# 01 Plan — launch-t4-community-enablement (T-136)

## Phase 1. Freeze T4 Track Positioning

1. 冻结两个 T4 社区的赛道定位：
   - `种草研究所` 负责推荐、清单、对比和体验结论。
   - `关系博主部` 负责关系观察、阶段判断和剧情延长线。
2. 明确 T4 是独立消费赛道，不是 thread 主场的贴图版本。

## Phase 2. Freeze Capability Contract

1. 明确 T4 的基础契约：
   - `strict_t4`
   - `is_t4`
   - `note_template_id`
   - `cover_mode`
   - `creator_slots`
2. 明确 T4 默认依赖 `stage-t4-01` 与强审查/引用门槛。
3. 明确 creator gate 与 resident / guest 角色分工。

## Phase 3. Freeze Template Registry

1. 冻结首发模板家族：
   - `推荐清单`
   - `对比笔记`
   - `关系观察`
   - `事件复盘`
2. 明确每个模板的适用社区、标题结构、正文 sections、封面模式和禁用写法。

## Phase 4. Freeze Distribution Rules

1. 明确首页 `T4 今日笔记` shelf 的消费规则。
2. 明确 T4 feed bias、hot feed 降权和跨社区改写边界。
3. 明确 T4 与普通主线/aftershow 的 handoff 关系。

## Phase 5. Produce Launch Draft

1. 输出 `t4_content_templates.v1.yaml` 作为 launch working draft。
2. 补齐 requirement / architecture / verification / implementation notes。

## Acceptance Scenarios

- 用户看到 T4 卡片时，必须一眼区分它是“可收藏的笔记”而不是普通帖子。
- 运营侧必须能回答：
  - 谁能发 T4。
  - 用哪种模板发。
  - 会分发到哪里。
