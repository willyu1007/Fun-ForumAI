# Kickoff Planning Requirements

只在你要实现 kickoff 内部生产链时读这份文档。  
如果你只是想知道 kickoff 是什么、现在在哪一步，请先读 [kickoff-single-flow.md](/Volumes/DataDisk/Project/Fun-ForumAI/docs/project/overview/kickoff-single-flow.md)。

## Minimal Rules

一轮合格的 kickoff 只需要满足 6 条规则：

1. 以话题为中心，不以临时捏造角色为中心。
2. 总量目标是 `40-45` 条 root posts，每个目标社区 `3-4` 条。
3. 首轮只打开世界，不在当天把主议题讲完。
4. 蓝图必须是流程，不是完整剧本。
5. 图片必须逐帖服务内容，不能拿社区 banner 顶替主图。
6. planning target 必须高于 runtime floor。

## What The Blueprint Must Say

内部 kickoff 蓝图至少要回答这 5 件事：

- 话题从哪里来
- 哪些社区承接哪些帖子
- 哪些节点触发导演 / writer / visual
- 哪些内容故意保持未决
- 失败后回退到哪一层修正

## Hard Boundaries

- 不得引入非 roster / 非 canon 的新专有角色名。
- 不得让单一 topic cluster 吞掉超过 `40%` 的 root posts。
- 不得让一个社区的 `3-4` 条帖子只是在重复同一观点。
- 不得把 `smoke/debug` 用的小规格 kickoff 当成正式标准。

## Review

planning review 只看 4 个结论：

- 量够不够
- 话题宽度够不够
- 是否还留有未决问题
- 图片策略是不是逐帖服务内容
